# 展板露出核查

展板送印前，核对每幅原片在展板上**实际露出**的部分是否都落在其**可刊矩形**内。
全部合规时才可下载署名 CSV。

## 启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

署名表默认暂存在 Docker 命名卷 `credit-data` 中，容器重启后仍在有效期内的
下载链接不受影响。可通过环境变量调整（也可写在同目录 `.env` 文件中）：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `CREDIT_STORE_MAX_BYTES` | `16777216`（16MB） | 署名表暂存总上限，按 CSV 文件实际字节数计 |
| `CREDIT_STORE_TTL_SECONDS` | `28800`（8 小时） | 下载链接有效期 |

本地开发（需 Python 3.11+）：

```bash
pip install -r requirements.txt
python app.py                    # http://localhost:8000，数据存于 ./data
python test_geometry.py          # 核心几何逻辑
python test_credit_store.py      # 暂存、过期与容量
python test_app.py               # 网页与下载路由
```

## 使用

1. 在首页上传描述 JSON（可下载页面上的示例对照格式）。
2. 结果页按原片列出：**露出面积**、**缺许可面积**；有缺口时给出**一处未获许可的原片坐标**。
3. 整页无缺口、且本次署名表保存成功后，结果页才出现「下载署名 CSV」按钮；
   CSV 只列实际露出的原片编号与署名。
4. 链接生效后 8 小时内可反复下载；后续核查不会挤掉仍在有效期内的表，服务重启后
   链接依旧可用（署名表落盘在 `CREDIT_STORE_DIR`）。
5. 链接到期后访问会提示重新核查，过期表占用的空间可被新表复用。若暂存空间不足或
   写入失败，仍照常显示本次核查报告，并说明为何无法下载；此前未过期的链接照常可用。

## JSON 格式

```json
{
  "board": {"width": 6000, "height": 4000},
  "photos": [
    {"id": "A-001", "credit": "陈晨",
     "permit": {"x": 0, "y": 0, "w": 2400, "h": 1600}}
  ],
  "pieces": [
    {"photo": "A-001",
     "crop": {"x": 100, "y": 80, "w": 1200, "h": 900},
     "at": {"x": 300, "y": 250}}
  ]
}
```

- `board`：展板尺寸，整数像素，宽高可达 100000。
- `photos`：原片清单。`permit` 为可刊矩形（原片坐标）。
- `pieces`：裁片，**从下往上**排列（数组越靠后层级越高）。`crop` 为原片裁框
  （原片坐标），`at` 为落版位置（裁框左上角在展板上的坐标）。
- 所有坐标为整数像素；矩形宽高的字段名 `w`/`h` 或 `width`/`height` 均可。
- 坐标系：原点左上，x 向右，y 向下；裁片按原尺寸铺放、互不透明。

## 计算规则

- 每片裁片的可见部分 = 其落版矩形（裁剪到展板内）减去所有更上层裁片的矩形。
- 可见部分平移回**原片坐标**后，同一原片多处的重叠区域只计一次（矩形并集）。
- 露出面积 = 并集面积；缺许可面积 = 并集中落在可刊矩形外的部分。

## 内存说明

核查全程只操作矩形列表（矩形差集 + 扫描线求并集面积），**不建立像素画布**，
内存占用只随裁片数量增长，与展板像素尺寸无关——十万像素见方的展板同样适用。
